# Contributing to Apoira

Apoira is a small public record, not a general-purpose framework. Changes
should preserve the distinction between the narrative experiment and the
mechanism that can actually be inspected.

## Before proposing a change

1. Open an issue describing the specific problem or improvement.
2. Keep the change narrow and avoid unrelated visual or narrative rewrites.
3. Preserve existing thought commits. Corrections should appear as descendants
   or explicit errata rather than silently changing an archived thought.
4. Keep claims honest about what is authored, deterministic, autonomous, or
   publicly anchored.

## Validate the record

```powershell
npm install
npm test
```

The test suite must pass before a change is proposed. New record mechanics
should include deterministic verification where practical.

## Contribution terms

By submitting software code, you agree that it may be distributed under the
MIT License. Do not submit narrative, artwork, identity assets, or third-party
material unless you created it and explicitly have the right to contribute it.
